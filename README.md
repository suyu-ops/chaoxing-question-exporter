> [!IMPORTANT]
> **本项目只做一件事：整理你有权查看的课程资料。**
> 它不刷课、不替考、不上传你的登录态、不把题目发到任何服务器（AI 功能除外——那把钥匙在你手里，请求直达你自己配置的服务商）。
> 页面结构可能随学习通更新而变化，导出前请自行核对题目与答案。

## 🏆 为什么敢说最强

市面上的学习通导出脚本，大多停在这三步：

**能抓题干 → 能导出 TXT → 能导出 Word。**

然后就没了。

而这个脚本在做的是另一件事——**它把"把题目留下来"当成一个完整工程来解决**：

| 别人卡住的地方 | 这里怎么解的 |
| --- | --- |
| 题干是一堆乱码方块，因为学习通上了 `font-cxsecret` 加密字体 | 内置 Typr.js + MD5 完整解密链，解析 `@font-face` 里的 base64 字体，按字形哈希反查映射表，把密文还原成正常汉字。**这一步是绝大多数脚本直接放弃的地方。** |
| 一门课四十多个任务点，手动点一晚上 | 整门课自动串起来跑，带三档节奏、随机抖动、长休息、指数退避，命中风控信号自动暂停 |
| 跑到第 30 章崩了，全部白干 | 每章落盘存档，刷新、崩溃、关标签后重新打开能接着跑 |
| 导出的卷子图片全丢 | 富文本保留：Word 走原生 OOXML `w:drawing` 嵌入真实图片资源，图片已在题库里则以〔图片1〕占位符形式保留 |
| 题库导入后全变成"单选题" | 按选项数、答案形态、空位标记推断题型，还给出置信度；信号冲突就老实扔进「待归类」而不是瞎猜 |
| 答案不准，得一条条手工对 | 接任意 OpenAI 兼容接口，单题补、批量补、全量审、随时停；每题带来源与置信度，题库里能按「低置信度」筛出来复核 |
| 想改题干只能重新导出一次 | 在线编辑器：改题干、改选项、增删选项、改答案、改解析、勾选导出范围，一次保存全生效 |
| 换台设备题库就没了 | 题库支持 JSON / TXT / Markdown / DOCX / PDF 五种格式导入导出，备份与迁移没有门槛 |

**它还是免费的、开源的、单文件的。**

不用注册、不用付费墙、不用登录第三方账号、不用装构建工具、不用 `npm install` 就能跑起来。下载一个 `.user.js`，扔进脚本管理器，就有了一整套工具链。

> 说句实话：「全网最强」是**主观评价**，也是这个项目给自己定的目标线。
> 但下面每一个数字、每一项能力，都能在源码和测试里逐条查到——**不含任何一句写在 README 里但代码里没有的功能。**

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 或 [Violentmonkey](https://violentmonkey.github.io/)。

- 支持 Chrome / Edge / Firefox 等主流内核浏览器

## 🔬 深度特性

### 一、加密字体解密：整个脚本技术含量最高的部分

学习通会在题干和选项上套一层 `font-cxsecret` 自定义字体：页面上肉眼看到的字是正常的，但 DOM 里躺着的是完全无关的码点。**这是所有复制、抓取、另存为方案集体失效的根本原因。**

这个脚本的处理链路是完整的：

```
<style> 里的 @font-face
   ↓  提取 base64 字体二进制（兼容无引号、无分号的畸形 CSS）
   ↓  Typr.js 解析 sfnt / OTF / TTC，逐字符取出字形轮廓
   ↓  对轮廓做归一化后算 MD5
   ↓  拿哈希去字体映射表反查真实字符
   ↓  按原顺序回写文本节点
```

细节上做了这些兜底：

- **`@font-face` 可能在 `<body>` 或动态容器里**，所以遍历全部 `<style>`，不只取第一个
- **Base64 允许换行**，以引号 / 右括号 / 分号界定结束，不在空白处提前截断
- **同一容器可能既含加密文本又含选项按钮**，优先改 `.after` 子节点，避免破坏按钮结构
- **父子元素重复命中**时只改最外层，不重复改写文本节点
- **映射表加载失败不缓存失败状态**，网络恢复后自动重试

解密失败时会往 `window.__xxt_font_cipher_debug` 写诊断信息（失败原因、目标元素数、样式表数），排查问题不用猜。

### 二、批量提取：把"像人一样"做成工程

整门课几十个任务点，一路点下去必然撞风控。三档节奏参数：

| 档位 | 每章间隔 | 长休息 | 44 章预计耗时 |
| --- | --- | --- | --- |
| **保守**（默认） | 12~22 秒 | 每 8~12 章休息 45~90 秒 | 约 24 分钟 |
| 标准 | 7~13 秒 | 每 12~18 章休息 25~50 秒 | 约 12 分钟 |
| 快速 | 4.2~7 秒 | 每 20~30 章休息 15~25 秒 | 约 7 分钟 |

保护机制不止于此：

- **随机抖动**：所有间隔都在区间内随机取值——固定间隔本身就是最明显的机器特征
- **硬下限**：两次真实跳转不低于 6 秒，误选快速档也不会高频
- **阶段性长休息**：模拟人离开一会儿
- **页面不可见时自动放慢**：切标签 / 最小化时等待放大 1.5~3 倍
- **失败指数退避**：连续失败逐步拉长等待，成功一章自动恢复
- **风控信号自动暂停**：命中 `403` / `429` /「操作过于频繁」/「验证码」立刻停，绝不越撞越狠

**断点续跑**：每章结束写入存档（关闭标签页前 `beforeunload` 再兜底一次）。页面崩溃、误刷新、关掉重开，面板会提示「检测到上次未完成的整门课提取」，点「继续提取」从断点接着跑。恢复时会重新扫描课程目录，把存档里的任务点对齐到当前页面真实节点——课程结构变了就跳过失效项，而不是整段失败。

存档超限时按比例削减（保留靠后的题，越接近进度越重要）并清空日志，而不是写入失败。正常跑完自动清档，不留垃圾。

### 三、题库：从"一次导出"到"长期资产"

- **多库管理**：按课程 / 章节分库，随时切换
- **多格式导入**：JSON、TXT、Markdown（`.md` / `.markdown`）、DOCX、PDF 都能吃进来，自动按题号、选项、答案、解析还原成结构化题目
- **DOCX 导入**用内置 ZIP 解析，不依赖第三方库
- **PDF 导入**按坐标聚行，避免整页文字糊成一段
- **题型自动推断**：没写题型的也能猜，依据是选项数量、答案形态（单字母 / 多字母 / 对错词）、题干空位标记（`______`、`（  ）`），并给出置信度
- **「待归类」机制**：信号不足或互相冲突时**不猜**，老实放进待归类分组，卡片上写明建议题型与依据
- **相似度对比**：当前页面题目与题库做模糊匹配，阈值可调（默认 90%）
- **导入识别报告**：导入完汇总题型分布、带答案 / 带解析题数、待归类数量

### 四、AI：你把钥匙给它，它才干活

接任意 OpenAI 兼容服务商——官方、中转、自建、本地跑的模型都行。填到 `/v1` 即可，脚本自动拼 `/chat/completions`。

四种用法：

| 按钮 | 作用 |
| --- | --- |
| 补充无答案题 | 只处理答案为空的题，不动已有答案 |
| 补全解析 | 只补解析，绝不改答案 |
| 审核全部题目 | 逐题复核答案与解析，给出纠正 |
| 处理勾选题目 | 只跑你选中的那几道 |

每题结果都会带上 **AI 来源 + 置信度 + 解析**，存进题库后标记不丢，随时能用「低置信度」筛出来人工复核。

**编辑器和题库的行为刻意不同**：题库区 AI 直接写入（有二次确认）；编辑器里 AI 只填输入框，你逐题核对后点「保存修改」才生效，点「取消」全部丢弃。

## ❓ 常见问题

<details>
<summary><b>面板没有出现怎么办？</b></summary>

确认脚本已启用、当前网址在学习通匹配范围内，然后刷新页面。首次进入需要等页面和依赖加载完成。仍然没有的话，打开 F12 控制台看有没有红色报错，或在脚本管理器里检查是否被其他扩展拦截。
</details>

<details>
<summary><b>为什么刚切换章节就提取到了上一页的题目？</b></summary>

学习通常把题目放在 iframe 或延迟加载区域里。切换后等题目完全显示，再点「重新提取」；批量流程本身会等当前任务点页面稳定后才读取。
</details>

<details>
<summary><b>为什么答案和平台显示不一致？</b></summary>

先确认平台是否真的公开了标准答案。如果页面只显示「我的答案」和评分，脚本会把**你的作答**保留为可编辑附加答案，而**不会**把它冒充成平台标准答案。请通过在线编辑或题库修改后再导出。
</details>

<details>
<summary><b>题目多的时候卡住不动 / 一直显示「正在识别题目…」？</b></summary>

1.11.2 已修复。324 题的作业页有 4 万多个 DOM 元素，旧版在字体解密前会对整页每个元素调一次 `getComputedStyle`（4.3 万次 / 8 秒左右），主线程被拖住后提取流程会掉进 iframe-only 分支返回空结果。现在页面没有加密字体时直接跳过这一步，324 题实测 `getComputedStyle` 调用降到 0 次、主线程最长阻塞从 21.6 秒降到 2.7 秒。如果更新后仍然卡，请按 F12 打开控制台看红色报错。
</details>

<details>
<summary><b>题干后面跟着答题框占位符或下一题题号？</b></summary>

1.11.2 已修复。作业作答页每题标题里都有一个「（简答题）」样式的小标签，旧版会把每个标签当成一个「题型分区」，用 Range 从本题截到下一题，把中间的内容一起卷进题干。现在单题容器内部的题型标签不再参与分区判定。
</details>

<details>
<summary><b>题干后面跟了一大段界面文字？</b></summary>

1.11.1 已修复。旧版本会把题库筛选下拉里的「单选题」「判断题」当成页面上的题型分区，截取题干时一路截到面板，把整块界面文案卷了进去。现在脚本自己的窗口（面板、设置、历史、题库、批量、编辑器、预览）都带统一标记并在提取时排除，`option`/`select`/`input` 等表单控件也不再参与题型判定。若仍遇到，请更新到最新版本。
</details>

<details>
<summary><b>题干或选项是一堆乱码方块？</b></summary>

这是学习通的加密字体没解开。在控制台执行 `__xxt_font_cipher_debug` 查看诊断：`reason` 会告诉你卡在哪一步（没找到目标元素 / 字体表加载失败 / 字形哈希没命中）。常见原因是网络不通导致映射表拉不到——换网络或挂代理后刷新重试。
</details>

<details>
<summary><b>Word / PDF 下载失败怎么办？</b></summary>

检查浏览器是否拦截了自动下载或弹窗，允许后重试。也可以先导出 TXT 或 Markdown 验证题目内容正常，再回到 Word / PDF。
</details>

<details>
<summary><b>题目数量不对怎么办？</b></summary>

部分页面需要滚动或切到已批阅详情后才会完整渲染。先确认页面上实际可见多少题，再重新提取。多章节场景请用「整门课提取」，并在日志里逐个确认任务点状态。
</details>

<details>
<summary><b>AI 配置保存后重开显示未配置？</b></summary>

历史记录存的是完整题目快照，条数多时可能撑满 localStorage（通常 5MB）。现在保存失败会**自动清理下载历史后重试**并提示，仍失败则原地显示错误、当前占用和处理建议。也可以在「历史记录」里手动删旧条目。
</details>

<details>
<summary><b>会不会把我提的题发到网上？</b></summary>

不会。除 AI 功能外，脚本不向任何服务器上传内容——AI 请求直达你配置的服务商地址，密钥只存本机 localStorage，不随题库导出。主面板里的「星夜题库」卡片只提供新标签页链接，不会自动上传题目、登录信息或题库数据。
</details>

<details>
<summary><b>为什么源码里要内嵌 Typr.js 和 MD5？</b></summary>

字体解密要在浏览器里解析字体二进制，这必须有字体解析器和哈希实现。把它们内嵌进单文件，就不用从第三方 CDN 加载（会被 CSP / CORS 拦），也不会触发 Greasy Fork 对压缩代码的审查限制。两个库都是 MIT 许可，版本与源码地址在脚本头部注释里已标注。
</details>

## 🛠️ 开发与反馈

### 回归测试

需要 Node 18+：

```bash
# 需要 jsdom 的用例（冒烟、对话框、复选框、编辑器流程）请先安装
npm i jsdom@30 --no-save

node .test/run-all.js
```

> **jsdom 版本必须锁 30.x。** 24 会让 dialog/smoke 失败，26/27 在 SVG 与 border 简写上行为不一致，31 会把 `1.5px` 边框塌缩成 `1px` 导致复选框用例假失败。未安装 jsdom 时相关用例自动跳过，其余仍会全量执行。

覆盖范围：

- 题目解析（TXT / MD / DOCX）、AI 应答归一化、题库规范化与 AI 标记持久化
- 待归类题的建议题型 / 归类依据持久化、批量 AI 归类不丢题
- 设置持久化与配额耗尽降级
- 导出内容选项、导出按钮事件时序
- 编辑器 AI 选靶与填入、复选框可见性
- 批量限速档位、随机抖动、风控信号识别、进度存档与恢复
- 声明时序静态扫描（TDZ）+ 整体冒烟（jsdom 真实执行脚本并点击全部按钮）

### 故障排查索引

| 现象 | 看这里 |
| --- | --- |
| 所有按钮都点不动 | 控制台报错 → 多半是 TDZ，见 1.9.1 条目 |
| 题型识别不对 | 见 1.8.3；也可在编辑器手动调整 |
| 导入后全是「待归类」，徽章只写「题型未知」 | 见 1.11.3（建议题型字段落盘丢失） |
| AI 归类后仍有题留在待归类，界面却说全部写入 | 见 1.11.3（批处理下标错位） |
| 题目很多时卡死、一直「正在识别题目…」 | 见 1.11.2（全页 `getComputedStyle` 扫描） |
| 题干里混进面板文案 | 见 1.11.1（自身 UI 被当成题型分区） |
| 勾选框看不见 | 见 1.8.3（宿主 `!important` 样式覆盖） |
| 点导出没反应 | 见 1.8.2（`event.currentTarget` 时序） |
| 设置保存不生效 | 打开「设置 → 本地存储占用」排查配额 |
| 题干是乱码方块 | 控制台执行 `__xxt_font_cipher_debug` |
